## 🤖 AI Change Summary for PR #42

### 개요
이번 패치는 사용자 인증 및 아이템 관리 기능을 개선하기 위한 여러 변경 사항을 포함하고 있습니다. 주요 내용으로는 오류 코드 수정, 보안 설정 변경, 소셜 로그인 기능 개선, API 응답 형식 변경, 페이지네이션 추가, 리프레시 토큰 처리 방식 변경, 그리고 상점 정보 조회 및 업데이트 기능 추가가 있습니다.

### 주요 변경 사항
1. **오류 코드 수정**:
   - `ErrorCode` enum에서 리프레시 토큰 관련 오류 코드의 상태 코드를 404에서 401로 변경하고, 새로운 오류 코드 `INVALID_STORE_NAME` 추가.

2. **보안 설정 변경**:
   - `SecurityConfig`에서 Google 로그인 경로를 대문자로 변경하고, 모든 인증 경로를 허용하도록 수정.

3. **소셜 로그인 개선**:
   - `AuthController`에서 소셜 로그인 로직을 개선하여 사용자 정보를 기반으로 액세스 및 리프레시 토큰을 생성하고 쿠키에 저장하도록 변경.

4. **API 응답 형식 변경**:
   - 여러 컨트롤러에서 API 응답 형식을 DTO를 사용하도록 수정하고, `updateNickname` 메서드에서 요청 파라미터를 `@RequestBody`로 변경.

5. **페이지네이션 추가**:
   - `MyTteokController`와 `TtoekgukController`에서 페이지네이션을 추가하여 데이터 조회 시 성능 개선.

6. **리프레시 토큰 처리 변경**:
   - `JwtTokenProvider`에서 리프레시 토큰을 쿠키에서 우선적으로 찾도록 변경.

7. **상점 정보 조회 및 업데이트 기능 추가**:
   - `StoreService`에서 `getItems` 메서드의 반환 타입을 변경하고, 상점 이름 업데이트 및 유효성 검사 기능 추가.

8. **DTO 수정**:
   - `AuthDto`에서 `refreshToken` 필드를 제거하고, 페이지네이션 정보를 포함하는 새로운 DTO 클래스 추가.

### 위험/영향
- **호환성 문제**: 기존 클라이언트가 새로운 오류 코드 및 API 응답 형식에 적응하지 못할 경우 문제가 발생할 수 있음.
- **기능적 영향**: 메서드 시그니처 변경으로 인해 기존 코드에서 수정이 필요할 수 있으며, 페이지네이션 추가로 인한 응답 형식 변경이 클라이언트에 영향을 줄 수 있음.
- **보안**: 소셜 로그인 및 리프레시 토큰 처리 로직 변경으로 인해 보안 취약점이 발생할 가능성이 있으므로 철저한 검증이 필요.

### 테스트/검증
- 모든 변경 사항에 대해 단위 테스트 및 통합 테스트를 수행하여 기능이 정상적으로 작동하는지 확인해야 함.
- 특히 소셜 로그인 및 리프레시 토큰 관련 기능, 페이지네이션 기능에 대한 테스트를 강화할 필요가 있음.

- 클라이언트와의 협의를 통해 API 변경 사항을 문서화하고, 필요한 경우 클라이언트 코드 업데이트를 지원해야 함.
